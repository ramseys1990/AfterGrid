# Mesh communications

Optional MeshMonitor 4.18.0 serves one native web interface for Meshtastic and MeshCore. Install from the portal; no automatic radio connection, public MQTT broker, USB passthrough or privileged mode. Initially bound to loopback port 8085. Native authentication is required and anonymous access is disabled. Reveal and save the generated initial administrator password in AfterGrid. Select **Share on LAN**, acknowledge trusted-LAN HTTP, then **Open application** and sign in with the native account. No SSH forwarding or additional account creation is needed for this proposed normal journey. If already configured, use the current native password instead. The updated shared-origin first-login test and physical LAN acceptance remain pending. Native users and permissions are managed in MeshMonitor. The initial password displayed by AfterGrid does not track subsequent native password changes.

Add a compatible Meshtastic TCP node in Sources, using its own LAN IP and TCP port (normally 4403). MeshCore sources may be added through the native UI with a supported TCP companion/repeater; verify device firmware and transport compatibility. No USB/serial or BLE bridge is installed in this slice. Use your own radios, appropriate regional radio settings, private channels and authorized recipients. Do not enable public MQTT or internet relay if offline/private operation is intended. Native map layers or other optional features may require internet; complete disconnected operation is not yet verified.

Only the web interface port is published. The native database is retained in data/meshmonitor and the generated credentials in the worker state. Protect backups and keep the worker state for recovery. LAN HTTP is unencrypted; prefer trusted LAN or a future TLS deployment. No automated messages, device configuration or live hardware test is performed. CI covers no-device startup, native login, sharing, lifecycle and retained data; results pending. See https://meshmonitor.org/getting-started.html for native setup.

See [interoperability review](../../docs/COMMUNICATIONS-INTEROP.md). Native TAK-related features exist upstream; AfterGrid does not expose the separate CoT feed or enable automatic bridging.
