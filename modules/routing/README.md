# Offline routing

Optional upstream Valhalla 3.9.3. Before installing, obtain a trusted regional OpenStreetMap .osm.pbf extract (e.g. Geofabrik), copy it to /opt/aftergrid/content/routing/region.osm.pbf and ensure the directory is writable by UID 10001. Existing development installs may need to create that directory. Start small; graph building can use substantial CPU, RAM and disk. Installation runs the native graph builder through a fixed Compose one-off command, then starts the native service. The graph is retained on uninstall and never automatically replaced. If it fails, inspect the job output. No direct internet download, administrator/timezone/elevation data, regional update UI or automatic rebuilding yet.

Open the route planner from the LAN portal. Choose longitude/latitude pairs or click the styled map, then select driving, walking or cycling. Route calculation is local; no cloud fallback. The backend has no published port; the portal exposes a bounded same-origin route endpoint after setup. The map archive and road graph are separate datasets and should cover the same area. Even without map tiles, coordinate-based directions can be requested. No live traffic or current closure data: verify road conditions. Native graph build and costing smoke tests are pending. For a new region, stop routing and archive its old graph before installing again with a new PBF. Do not change data while building.

Saved plans: portal administrators can add public LAN waypoints and save displayed route geometry. Guests may view the points, use them for routing and export GPX/KML. Saved geometry is available even with routing stopped; it is not recalculated or checked for current road conditions. No private waypoint access or live GPS tracking. Imports and address search remain planned.

Local GPX/KML import supports UTF-8 files up to 1 MB, points and line/track geometry. Separate GPX segments are saved separately. KML external network links, unsupported placemark geometry and XML entities are rejected; no external content is fetched. Imports are atomic and shared on the LAN. Imported routes are static geometry, not calculated navigation directions. Complex styling, overlays, elevation and timestamps are not imported.

Regional data download: administrator portal supports initial Geofabrik presets. The first verified source becomes region.osm.pbf; subsequent downloads stage as incoming.osm.pbf. Existing graph and source are untouched. Published MD5 verifies transfer integrity, not cryptographic authenticity beyond HTTPS. The 2 GiB PBF limit and 512 MiB reserve are development defaults, not a graph-build resource estimate. Do not replace the source while a graph build is running. Replacement activation/rollback remains an operator-controlled manual workflow until the next slice. No automatic rebuild, resume, or live upstream acceptance yet.

## Replacement and rollback

After downloading or manually staging incoming.osm.pbf, select Prepare replacement graph in the administrator portal. It builds tiles-next without changing tiles or the active selector. The graph build requires minimum free space of three times PBF size plus 512 MiB (not a guarantee of sufficient total disk or RAM), and has a 25-minute native build limit. Activate replacement when the candidate is ready and routing is running; the worker checks both slots, stops routing, atomically selects the new slot, starts and checks readiness. A failed switch attempts to restore the prior slot and restart. Roll back to original uses the same sequence. Readiness is a service status probe, not proof that every route is valid; verify actual routes after switching. Both source files and both graph directories remain. Repeat updates by explicitly archiving the inactive graph/source pair, downloading into that vacant slot and preparing it. No deletion UI yet. If the worker is interrupted, inspect the selected-on-disk slot and actual app state, then Start routing or roll back when ready. Never alter graph directories during graph maintenance. Browser/physical LAN acceptance and real different-region swap remain pending.

## Place search and alternatives

Build the local search index in the map page as administrator. Osmium filters named and house-number nodes from the selected PBF and exports points; SQLite FTS5 indexes names, tagged street addresses, locality and type. All LAN users can search after setup. No online geocoder, full address interpolation, polygon POIs, reverse geocoding or guarantees of completeness. Initial limits: one million points, 512 MiB native output cap, 1.5 GiB extraction virtual-memory cap and 2 GiB free-space admission. Source file metadata changes invalidate the selected index; graph switching selects its own index. Build again if absent. Search does not need Valhalla running. The route planner can request up to two native alternatives; select one to display directions or save the geometry. An alternative may not exist. Native fixture search, actual alternate route generation and browser acceptance still need validation.

The two slot names are fixed: A = tiles / region.osm.pbf, B = tiles-next / incoming.osm.pbf. Switch either way. While routing is running, archive the inactive slot only after confirming the current graph works. Archiving moves both files/directories into a unique retained directory under content/routing/archives. It does not reclaim disk. An interrupted archive can leave a partial retained pair; inspect archives and restore the pair manually before reusing an occupied slot. The portal never removes an archive, and archive recovery is manual. This is not backup; keep independent Kopia backups. New real second-cycle smoke tests are pending.
